TicketZero

A support-agent kit for SideShift, built by Keshvi Pipwala · Code

Every ticket goes through the same loop: classify it, run the account checks a support engineer would run, decide whether the agent can answer alone, and draft the reply. Every miss becomes a rule and a test, so the agent handles it next time. It never moves money, lifts a hold or deletes data on its own.

    Connect webhook debugger

    For developers on SideShift Connect. It checks a signature the way SideShift signs it (HMAC-SHA256 over the timestamp, a dot and the raw body), and when it fails, re-signs the payload with each common mistake to say which one their code makes.

    Signature check

    Load an example, or paste a real delivery and the signature your code computed.

    Delivery log triage

    Paste the response of GET /api/embed/webhook-logs. It finds events that were never delivered, explains why, and writes the replay commands.

    How it's measured

    Each round, I froze the rules, wrote a fresh batch of tickets the agent had never seen, and scored it as-is. Then every miss became knowledge for the next version. The number that matters most is the last column: wrong answers sent without a person.

    Blind rounds

      The loop

      1. A ticket the agent can't classify goes to a person, never to a guess.
      2. The person resolves it. The fix becomes a rule, a reply and a test case.
      3. The rules are frozen and scored on tickets nobody tuned against.
      4. The CI suite fails if any money-moving ticket would ever be auto-answered.

      Public complaints, and the product change that removes each one

      All 14 reviews on SideShift's Trustpilot page (unclaimed, all one-star, read on October 14, 2026), coded by theme. A small, skewed sample, but every theme also shows up in the Terms, the docs or app reviews. Agents answer tickets; the bigger win is deleting the reason for them.

      The help page doesn't cover what creators ask about

      The public customer-support page (read October 14, 2026) answers 9 questions. All 9 are for brands: pricing, trials, plans, ads, cancellation. None covers withdrawals, identity checks, holds, the 5-day review window or deleting an account, which are the topics creators complain about in public. The five runbooks in this kit can go up as help articles this week, and once they're in Intercom, its AI agent can answer from them.

        What I would ship in the first 30 days

        1. Week 1: own the queue

          Work Intercom and Slack tickets end to end, tag every one by type and root cause, and write the first 10 runbooks from real resolutions.

        2. Weeks 2–3: agent resolves money questions

          Ship withdrawal status, review-window and deposit-fee answers to the agent with the guardrails above, and measure how many resolve with no human touch.

        3. Week 4: delete tickets

          Bring engineering the top three root causes with counts, starting with self-serve account deletion and withdrawal status in the app.
